# 小特征丢失：完整调查记录

> 触发问题：「该 skill 在绘制后出现了画面中的角色没有嘴的情况」
> 调查日期：2026-10-23
> 结论：**单点参数无法修复；这是量化容量与面积分配的乘积性约束**

---

## 一、缺陷的确证

测试图：`input/collections/batch3/illust_100531443_20260808_134010.png`（805×1300）

原图有嘴（浅色内腔 + 深色唇缘），矢量化后该区域是平整的皮肤色块，**嘴完全消失**。

关键测量（嘴部框 x385-425, y425-458）：

| 量 | 数值 |
|---|---|
| 源图最暗像素 | RGB(37,21,22)，亮度 **27** |
| 皮肤中位亮度 | 222 |
| 亮度对比 | **194**（对比度极强，不是"看不清"） |
| 嘴部暗像素（<182） | **18 个** |
| 暗区连通块面积 | **[10, 6, 2] px** |
| 占全图面积比 | **0.0017%** |

---

## 二、根因链（四层，逐层实测）

### 第 1 层：平滑阶段抹掉暗极值

`vec3.py` 在量化前做**两次 3×3 中值滤波**：

| 阶段 | 框内亮度最小值 | <182 像素数 |
|---|---|---|
| 源图 `orig` | 26.7 | **18** |
| 两次中值后 `sm` | **149.7** | **2** |
| 进 KMeans 的 `edge_sm` | 110.2 | 9 |

源图最暗的 18 个像素（27, 49, 60, 72, 79…）经平滑后变成（150, 150, 184, 187, 196…），**只剩 2 个**仍低于阈值。

> 注意：保边混合 `edge_sm = sm*(1-wk) + orig*wk` 中
> `wk = clip(grad/gmax * EDGE_KEEP * 3, 0, 1)`。
> 默认 `EDGE_KEEP=0.16` 时，即使最强边缘 `wk` 也只有 **0.48**——
> 超过一半仍来自被抹平的 `sm`。这是设计缺陷。

### 第 2 层：量化器分不到中心

KMeans 最小化**总平方误差**。18 个近黑像素在一个 104 万像素、以浅色为主的画面里贡献的误差可忽略，中心永远分配给皮肤/头发/背景。

**面积份额对照**：
- 嘴部暗区：全图的 **0.0017%**
- N=56 时每个中心平均覆盖：**1.79%**

差 1000 倍。从预算角度，给它独立中心在数学上是"不划算"的。

### 第 3 层：清理阶段整块清除

`VEC_SPECK=24`（小于 24 px 的连通块视为噪点，用最近邻颜色填充）。
嘴部最大连通块 **10 px** < 24，无论量化得多准，都会被整块清除。

### 第 4 层：闭合性——四层是乘积关系

任何单层修复都无效：
- 只修平滑 → 暗像素能到量化，但分不到中心
- 只修量化 → 送进去的图里已经没有暗像素
- 只修清理 → 前面已丢失，无物可清

## 三、六种已实测否证的方案

### 1. 提高 `EDGE_KEEP`（0.16 → 1.0）

| EDGE_KEEP | mouth MAE | 嘴px | starry bnd |
|---|---|---|---|
| 0.16（基线） | 9.028 | **0** | 14.01 |
| 0.30 | 9.037 | 0 | 15.48 |
| 0.50 | 9.060 | 0 | 18.33 |
| 0.75 | 9.186 | 0 | **23.05** |
| 1.00 | 9.208 | 0 | 21.55 |

`EDGE_KEEP=1.0` 时源图 18 个暗像素**全部存活到量化阶段**（已验证），但输出仍是 0——
因为卡在第 2、3 层。代价：星空图 bnd 从 14 猛增到 21~23。

### 2. 清理全开（`MINAREA=1` + `SPECK=1`）

| 配置 | 嘴px | mouth MAE | 体积 |
|---|---|---|---|
| 基线 | 0 | 9.028 | 2.22 MB |
| 只开 SPECK | 0 | 10.66 | 2.30 MB |
| 两门全开 | **3** | 9.528 | **5.37 MB（+142%）** |

即使把清理全开，也只能救回 **3/18** 像素，且体积暴涨。

### 3. 细长块豁免（`VEC_SPECK_ASPECT`）

按长宽比豁免 SPECK（嘴是 10×2 细条）。分支确认生效（豁免 1591 个块），
但 SFF 从 17.5% 变成 **17.3%**，无改善。原因：这些块在更早阶段已丢失。

### 4. 暗端配额（`VEC_DARK_K`，独立子智能体实现）

给极暗区间预留聚类中心。实现合规（默认关闭、逐字节不变、按占比取阈值防静默失效），
但：框内最暗中心降到 L\*=9.6，嘴部暗像素仍只有 **0~6**，且**星空图 bnd 退化 35~41%**。

### 5. 残差覆盖层（独立子智能体实现）

基础 SVG 之上叠加残差路径。能把嘴部暗像素从 0 恢复到 **21**，颜色确实取自源图，
但引入虫蛀伪影。决定性数据：thr45 时新增 3753 个跳变像素，
其中 **3742 个（99.7%）在嘴部框外**，源图梯度中位数仅 1.05——
**缺陷与噪声在面积/色差/边缘强度三个维度完全重叠，不可分离**。

### 6. 提高色数 `VEC_N`

| N | 总 SFF | mouth MAE | portrait MAE | dark MAE | wuther MAE | user MAE |
|---|---|---|---|---|---|---|
| 56（默认） | 17.5% | 9.028 | 6.631 | **7.955** | 11.356 | **8.619** |
| 96 | 21.4% | 8.599 | 6.352 | 8.235 | 10.975 | 9.556 |
| 128 | 26.7% | **8.589** | 6.198 | 8.839 | **10.974** | 9.576 |
| 192 | **42.9%** | 8.719 | **6.193** | 9.442 | **13.961** | 9.868 |

SFF 确实随 N 单调上升（17.5% → 42.9%），但 **MAE 有升有降**：
`dark` 和 `user` 在 N=56 就是最优，提 N 分别恶化 19% / 14%。

嘴部即使 N=192 也只有改善、未能恢复真实形状。

## 四、判据路线：三种尝试全部失败

想按图自动选择 N，试了三种判据：

| 判据 | 结果 |
|---|---|
| 小特征密度 | 全部饱和到 N=192（密度分布 p20=758, p80=1859，初设 60~400 完全脱离实际） |
| 小特征色差中位数 | **反向**：被预判为"噪声图"的 wuther 色差最高（17.3） |
| 低 N 试跑的 MAE | 相关系数 **r = -0.167**，无预测力 |

**结论：图像特征无法可靠预测「提 N 是否有收益」。** 收益幅度（+3.4%~+6.6%）
与风险幅度（-11.1%）同量级，淹没在图像差异里。

## 五、唯一可用的产出一：SFF 指标

`skill/tools/analysis/sff_index.py` —— Small Feature Fidelity。

此前项目只有 MAE / art / bnd / hfKept 四个指标，**都无法度量"小细节丢失"**。
SFF 填补了这个空白：

```
小特征 = 源图中面积 4~400 px 且与周围色差 >= 40 的连通块
SFF = 渲染图中仍然存在（色差 >= 25）的小特征数 / 源图小特征总数
```

基线值：**17.5%**（434 个源特征，保留 76 个）。

逐图基线：

| 图 | 源特征 | 保留 | SFF |
|---|---|---|---|
| mouth | 46 | 23 | 50.0% |
| portrait | 39 | 3 | **7.7%** |
| wuther | 348 | 49 | 14.1% |
| user | 1 | 1 | 100% |

`portrait` 只有 7.7%，说明**这是系统性问题，不只嘴部**。

## 六、给后续工作的建议

1. **不要再单点调参**。四层是乘积关系，六种方案已否证。
2. **若必须修复小特征，需要结构性改动**：把「高对比度小连通块」从主量化中剥离，
   用独立的面积预算处理（但残差层已验证会引入碎斑，需要新的分离判据）。
3. **优先用 SFF 度量这类缺陷**，不要只看 MAE——MAE 对小面积特征完全不敏感。
4. **提高 N 是双刃剑**：对高细节插画有效（最多 +6.6%），对扁平/暗色图有害（最多 -11.1%）。
   在没有可靠判据前，**默认 N=56 是稳妥选择**。

## 附：调查过程中的方法论错误（供后来者避坑）

| 错误 | 代价 |
|---|---|
| 三次靠目测猜裁剪坐标 | 全部猜错，浪费数轮 |
| 写自动找脸检测器 | 锁到衣服格纹上，失效 |
| 写两个"彩色描边"指标 | 都测不出真实差异 |
| 把"KMeans 分不到中心"当归因 | 实际是平滑阶段就已经没了 |
| 改 `vec3.py` 忘同步部署副本 | 一整轮测试无效（坑 19，本项目第二次） |
| 只测 N 的端点（56/192） | 误判 wuther 曲线形状（实际 N=128 最优） |
| 事后猜测 wuther 是"噪声图" | 色差数据否证，猜反了 |

**最重要的教训**：先确证「信号在哪一层丢失」，再动手改那一层。
本次花了大量轮次在错误的层上打补丁。
