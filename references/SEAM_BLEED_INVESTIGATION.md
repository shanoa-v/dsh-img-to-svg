# 亚像素接缝渗色：本项目最根本的渲染缺陷

> 发现日期：2026-10-26
> 状态：**已修复（`VEC_SEAL` + `VEC_BASECOL`），79 张实测 100% 改善、零退化**

---

## 一、现象

Noyu 组（浅色调精细插画，42 张）基线 MAE 中位 **13.093**，最差 21.271。
目视：深褐色与橄榄绿被渲染成浅黄泛白色调，整体"发灰发白"。

早期诊断显示：
- 有符号误差 R +13.25 / G +15.81 / B +12.75（三通道全正 = 整体偏亮）
- 暗部（源 L<80，占 33.1%）偏差 **+28.43**
- 色阶保留率仅 **16.4%**

---

## 二、逐阶段追踪：破坏发生在量化之后

用 `runpy` 跑真实管线导出中间量，分别重建栅格与原图比较
（`skill/tools/trace_pipeline.py`）：

| 阶段 | MAE | 暗部偏差 | 全局偏差 |
|---|---|---|---|
| LANCZOS 缩放后原图 | 0 | 0 | 0 |
| 两遍 3×3 中值滤波 | 5.944 | +4.02 | +0.76 |
| 保边混合 edge_sm | 5.088 | +3.38 | +0.63 |
| **量化后 cen[idx]** | **11.183** | **+4.24** | **+1.13** |
| **最终渲染 PNG** | **21.271** | **+28.43** | **+13.94** |

**量化后暗部偏差只有 +4.24，最终渲染变成 +28.43。**

从"量化"到"最终渲染"多了 +24 的暗部偏差，而这两个阶段之间只有
簇合并、碎斑清理、描摹、写 SVG。这是第一个关键线索。

---

## 三、排除法：不是 SPECK，不是碎斑清理

改 `VEC_SPECK` 从 24 到 2，merged 像素从 221132 降到 58093（**-74%**）：

| SPECK | merged px | MAE | 暗部偏差 |
|---|---|---|---|
| 24（默认） | 221132 | **21.271** | +28.43 |
| 2 | 58093 | 24.126 | +33.72 |
| 0 | — | 32.700 | +49.67 |

**清理幅度少了 74%，MAE 几乎不动，SPECK=2 反而更差。**

类似地，把 `SPECK`/`MIN_AREA` 按画布尺寸缩放（`VEC_ADAPT`），
六张跨尺寸图改善全部 **<0.07%**，线稿保留率一个百分点没变。

**结论：碎斑清理不是元凶。**

---

## 四、根因：底色从色块缝隙渗上来

### 4.1 决定性实验：只改底色一个属性

只把 `<rect fill="#FCE1B1">` 换成别的颜色，其余字节不动：

| 底色 | MAE | 暗部偏差 | 全局偏差 |
|---|---|---|---|
| `#FCE1B1`（现状，L=218） | **21.271** | +28.43 | +13.94 |
| `#6B4431`（边缘中位） | **15.328** | **+7.51** | -4.31 |
| `#724E3F`（边缘均值） | 15.143 | +8.52 | -3.01 |
| `#AD734D`（全图中位） | 15.244 | +17.00 | +1.65 |
| 纯黑 | 20.593 | -3.739 | -13.81 |
| 纯白 | 25.284 | +32.91 | +18.63 |

**只改一个属性，MAE 从 21.271 降到 15.328（-27.9%），暗部偏差从 +28.43 降到 +7.51（-73.6%）。**

### 4.2 但底色并不是"大面积裸露"

把 `<rect>` 填成纯品红后渲染，接近纯品红的像素只占 **3.89%**
（严格判据下 0.63%）。底色并没有"铺满画面"。

### 4.3 真实机制：逐像素反解 alpha

用纯黑与纯白两个极端底色渲染**同一个 SVG**，解方程求每个像素的实际 alpha：

```
rend_black = a·fg + (1-a)·0
rend_white = a·fg + (1-a)·255
=> (1-a) = (rend_white - rend_black) / 255
```

实测（Noyu 600×853）：

| 指标 | 值 |
|---|---|
| **alpha 均值** | **0.8728** |
| alpha 中位 | 1.0000 |
| **alpha < 0.999 占比** | **45.08%** |
| alpha < 0.95 占比 | 43.46% |
| alpha < 0.5 占比 | 5.57% |
| **暗部中 alpha<0.999** | **49.73%** |

**平均 12.7% 的底色从缝隙里透上来，暗部近一半像素受影响。**

机制：相邻色块各自描摹成独立 `<path>`，路径彼此贴合，
但光栅化对每条边独立抗锯齿，两条边都达不到 alpha=1，
于是底色从这条亚像素缝隙里渗上来。

**渲染模型 `rend = alpha·fg + (1-alpha)·bg` 精确成立**，
两次不同底色渲染的预测变化与实测相关系数 **0.99992**。

## 五、修复

### 5.1 补缝：给每个 path 加同色细描边（`VEC_SEAL`）

```xml
<path fill="#AABBCC" d="..."/>
  -> <path fill="#AABBCC" stroke="#AABBCC" stroke-width="1.0" d="..."/>
```

同色是关键：只填死缝隙，不改任何颜色，不产生描边感。

实测宽度选择：

| stroke-width | MAE | 暗部偏差 |
|---|---|---|
| 基线 | 21.271 | +28.43 |
| 0.6 | 14.923 | +12.38 |
| 0.8 | 14.445 | +9.23 |
| **1.0** | **14.433** | **+6.51** |
| 1.2 | 14.403 | +5.25 |

取 1.0 为默认：MAE 与 1.2 几乎持平，边缘更干净。

### 5.2 底色改取背景色（`VEC_BASECOL`）

原逻辑 `base_ci = argmax(cnt)` 取"像素最多的簇"。这在暗调图上会选中
不合适的颜色（本例 `#FCE1B1`，亮度 218，而源图中位亮度 122）。

新逻辑：
1. 取源图上下左右各 6% 的边框带（几乎必然是背景）
2. 求中位色（对少数侵入边框的主体像素稳健）
3. 在调色板中找**离该中位色最近的簇**作为 base_ci

保留"选调色板中真实存在的簇"这一点很重要——它让坑 18 的
层绘制顺序保护逻辑（`layers.sort` 把匹配 base 的层排最前）继续有效。

### 5.3 两者独立有效、可叠加

| 方案 | MAE | 暗部偏差 |
|---|---|---|
| 基线 | 21.271 | +28.43 |
| 仅换底色 | 15.328 | +8.11 |
| 仅补缝 1.0 | 14.433 | +6.51 |
| **补缝 0.8 + 换底色** | **13.474** | **+4.54** |

## 七、为什么之前一直没发现

1. **底色在亮图上是"恰好对的"**。白底图的 argmax 簇通常就是白/浅色，
   接缝渗上来恰好也是浅色，看不出问题。
2. **MAE 会稀释局部灾难**。392×392 白底图的暗部偏差 +109.94，
   但全图 MAE 只有 24.8——被 89% 的白色背景稀释掉了。
3. **以为问题在量化**。量化后暗部偏差只有 +4.24，看起来"正常"，
   没想到最后一步渲染又加了 +24。

## 八、两个被否证的修复方向（记录下来，避免重走）

在与接缝渗色并列的分析中，还追查了两个方向，**最终都被实测否证**。

### 8.1 否证 A：尺寸自适应 SPECK/MIN_AREA（`VEC_ADAPT`）

假设：`SPECK=24` 是绝对像素数，在 392px 小图上是 6×4 的块，
会抹掉 1-2px 宽的描边；应该按画布尺寸缩放。

实测（`VEC_ADAPT=1`，六张跨尺寸图）：

| 图 | 基线 MAE | 自适应 MAE | 改善 | 线稿保留 |
|---|---|---|---|---|
| 392 小 | 24.800 | 24.799 | **-0.00%** | 39.3% → 39.3% |
| 600 小 | 21.271 | 21.259 | -0.06% | 78.3% → 78.3% |
| 1000 中 | 13.431 | 13.426 | -0.04% | 65.3% → 65.3% |
| 1920 中 | 10.112 | 10.112 | 0.00% | 53.5% → 53.5% |
| 2894 大 | 4.220 | 4.220 | 0.00% | 83.1% → 83.1% |

**改善全部 <0.07%，线稿保留率一个百分点都没变。**

（更早还做过一轮 `VEC_SPECK` 24→2→0 的直接扫描，
merged 像素减少 74% 而 MAE 几乎不动，SPECK=2 反而恶化。
清理并非线稿丢失的原因。）

### 8.2 否证 B：高斯替代中值滤波（`VEC_SMOOTH=1`）

假设：中值滤波是序统计量，1-2px 深色描边在 3×3 窗口里是少数派被替换掉，
换成加权平均的高斯能保住线稿。

线稿保留率确实提高了：

| 滤波 | 线稿保留率 | 线稿处亮度 |
|---|---|---|
| 原图 | 100.0% | 56.3 |
| 两遍 3×3 中值（默认） | 67.1% | 119.2 |
| 高斯 σ=0.6 | **99.6%** | **85.6** |

**但叠加在组合修复之上时，六张图 MAE 全部恶化：**

| 图 | 中值+组合修复 | 高斯+组合修复 | 变化 |
|---|---|---|---|
| noyu 小 | 13.763 | 13.811 | +0.35% |
| noyu 线稿 | 10.357 | 10.643 | +2.76% |
| pixiv 小 | 22.429 | 23.836 | +6.27% |
| pixiv 中 | 9.558 | 10.214 | +6.86% |
| 梅原生 | 8.376 | 8.566 | +2.27% |
| 大图 | 4.181 | 4.366 | +4.44% |

**六张全部变差，无一张改善。**

结论：中值滤波的降噪价值大于它造成的线稿损伤。这是**取舍**，不是缺陷。
`VEC_SMOOTH` 开关保留（默认 0）作为实验接口，但**不应默认开启**。
