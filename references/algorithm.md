# 算法原理与选型

---

## 一、核心思想：矢量化不是"描边"，而是"色彩分层"

很多人以为把位图转矢量就是"提取轮廓线再描一遍"。这只对纯线稿有效。

对彩色插画/照片，正确的做法是：

> **把图像量化成 N 种颜色，每种颜色提取闭合轮廓，按面积从大到小堆叠覆盖。**

这样得到的是**真正的矢量图形**（纯 `<path>`，无位图嵌入），
且能表现连续色调——因为用 N 个色块近似了原来的连续渐变。

---

## 二、完整流程

```
位图
 │
 ├─ 1. 缩放至工作分辨率（默认 1:1，不降采样）
 │
 ├─ 2. 保边平滑 ★最关键
 │     中值滤波 ×2 去 JPEG 噪
 │     按梯度权重回混原图，保住边缘
 │
 ├─ 3. LAB 空间 KMeans 量化 → N 色调色板
 │
 ├─ 4. 碎斑清理（<24px 连通块用邻域众数替换）
 │
 ├─ 5. 逐层轮廓提取（skimage.measure.find_contours）
 │     注意 (row,col) → (x,y) 转置
 │
 ├─ 6. RDP 简化（按层面积自动分档 eps）
 │
 ├─ 7. 多边形 → 平滑 path（中点二次贝塞尔）
 │
 └─ 8. 按面积从大到小堆叠 + 底色板
        │
        └─ SVG
```

## 三、关键步骤详解

### 3.1 保边平滑（精度提升最大的一步）

```python
med  = 原图.中值滤波(3) × 2        # 去噪
grad = |∇gray|                     # 梯度强度
w    = clip(grad / percentile(grad,99), 0, 1) × VEC_EDGE × 3
out  = med × (1-w) + 原图 × w       # 梯度大处保留原图
```

**直觉**：平坦区域梯度小 → 用平滑值（去噪）；边缘处梯度大 → 用原图（保锐）。

**实测收益**：鸣潮海报 90.8% → 95.7%，**+4.9 个百分点**。

### 3.2 为什么用 LAB 而非 RGB 聚类

LAB 是**感知均匀**的色彩空间：数值上的距离更接近人眼感知的差异。

在 RGB 里，两个颜色数值差相同但视觉差异可能差很多（尤其深色区和饱和度边界）。
用 RGB 聚类会导致灰阶层次丢失、暗部糊成一片。

**实测**：从 RGB median-cut 换成 LAB KMeans，鸣潮海报 90.8% → 93.6%。

### 3.3 绘制顺序：为什么大的先画

后画的层覆盖先画的层。所以：

- **大面积层先画**（当背景）→ 比如天空、底色
- **小面积层后画**（当细节）→ 比如五官、高光

按 `np.argsort(-counts)` 排序即可（counts 是各色像素数）。

### 3.4 RDP 简化的自适应分档

大面积层有很长的边界，如果 eps 太小会产生几万个点，文件爆炸。
小面积层（细节）需要小 eps 才能保住形状。

```python
frac = 该层像素数 / 总像素数
eps  = VEC_EPS × (1.0 if frac < 0.02      # 小层：精细
                 else 1.3 if frac < 0.10  # 中层：折中
                 else 1.8)                # 大层：粗暴简化
```

### 3.5 贝塞尔平滑替代折线

直接用 RDP 后的多边形，边缘会有明显折角。用**中点作控制点**的二次贝塞尔：

```
从 P0 到 P1，控制点取 P0，终点取 P0P1 中点
```

这样曲线穿过所有相邻点的中点，天然平滑，且不需要额外的拟合计算。

## 四、方案对比与选型

| 方案 | 原理 | 适用 | 不适用 | 本 skill |
|---|---|---|---|---|
| **量化分层描摹** | 色彩分层 + 轮廓追踪 | 照片、插画、厚涂、复杂海报 | 纯图标（路径冗余） | ✅ 本方案 |
| **potrace** | 边缘追踪，单色 | 纯黑白线稿 | 彩色图（要自己拆通道） | ❌ |
| **手工重绘 SVG** | 人/AI 理解语义后重写 | 图表、UI 截图、示意图 | 复杂插画（画不出） | ❌ |
| **vtracer / autotrace** | 彩色分层追踪 | 通用彩色图 | 需要额外安装二进制 | ❌ |
| **内嵌位图**（`<image>` base64） | 不转换，直接包 | — | **伪矢量，放大就糊** | ❌ 禁止 |

### ❌ 一定要避免的作弊做法

```xml
<!-- 这不是矢量化！有人会这样糊弄 -->
<svg viewBox="0 0 1920 1080">
  <image href="data:image/png;base64,iVBORw0KGgo..." width="1920" height="1080"/>
</svg>
```

看起来和原图一模一样，相似度 100%，但**本质还是位图**：
放大就糊，无法编辑，文件还是那么大。**必须确认产出是真实 path。**

验证方法：检查 SVG 里有没有 `href=` 或 `base64`。

## 五、已知局限与原因

### 5.1 细笔画"融化"

**现象**：小字号文字、细 logo 的笔画变粗、边缘发糊。

**原因**：量化是逐像素归类。一个笔画宽度 1-2 px 的线条，
其边缘像素的颜色是**抗锯齿产生的过渡色**，会被归到相邻的某一层，
导致笔画变粗或断线。

**缓解**：
- 提高工作分辨率（`VEC_W` 保持 1:1）
- 分区处理：把文字区单独裁出来高分辨率描摹，再叠回主图

**无法根治**——这是色块拟合细线的固有代价。

### 5.2 体积大

1920×1080 约 5-10 MB。原因是路径点数量大。

**缓解**：降 `VEC_N`（64→40）、升 `VEC_EPS`（0.3→0.45）、降 `VEC_W`（有损）。

### 5.3 边缘色带

量化后相邻层之间存在颜色跳变，放大看有轻微色带感。

**缓解**：提高 `VEC_N`。但在 95%+ 相似度后收益递减。

## 六、可探索的改进方向（未验证）

1. **Oklab 替代 LAB** —— 感知更均匀，理论上量化更准
2. **边缘导向的量化** —— 在边缘处用更多色阶，平坦区用少色阶
3. **路径数据压缩** —— 量化坐标精度（1 位小数 → 整数）可减小 20-30% 体积
4. **分区自适应色数** —— 人物区 64 色，背景区 32 色
5. **文字区单独 OCR + 重排** —— 既能保证文字清晰又能编辑

## 七、相似度指标定义

```
MAE   = mean(|原图 - 渲染图|)              平均绝对误差，0-255
RMSE  = sqrt(mean((原图-渲染图)²))         均方根误差
PSNR  = 20·log10(255/RMSE)                峰值信噪比，dB
相似度 = (1 - MAE/255) × 100%              直观百分比
```

**为什么用 MAE 而非 SSIM**：MAE 计算简单、可解释（"平均每个像素差 N 个色阶"），
且对均匀色偏敏感。SSIM 更贴近人眼但对局部差异不敏感，容易掩盖问题。

**健康区间**：MAE < 12、PSNR > 20 dB、相似度 95-97%。
