# 参数调优手册

所有参数均来自本会话 4 张图的实测数据。

---

## 一、`VEC_EDGE` —— 保边强度（**最重要的调参项**）

### 原理

量化前先做平滑以去除 JPEG 噪点，但过度平滑会糊掉边缘。
做法是按**梯度大小**加权回混原图：梯度大（边缘）处多保留原图，梯度小（平坦区）处用平滑值。

```python
w = clip(grad / percentile(grad, 99), 0, 1) * VEC_EDGE * 3
result = smoothed * (1 - w) + original * w
```

`VEC_EDGE` 越大 → 保留原图越多（越锐利但噪点也多）。
`VEC_EDGE = 0` → 全平滑（用于对照实验）。

### 分档建议

| 图片类型 | 建议值 | 判断特征 | 原因 |
|---|---|---|---|
| 硬边线稿 / 扁平色海报 | 0.20 ~ 0.25 | 边缘强度 p50 > 8；主色占比 >25% | 边缘本来就锐，多保边保住细节 |
| 一般插画 / 立绘 | 0.14 ~ 0.16 | 边缘强度 p50 在 4-8 | 默认档 |
| 柔和厚涂 / 粉彩渐变 | 0.08 ~ 0.12 | 边缘强度 p50 < 4；59%+ 像素饱和度 <0.2 | 边缘本来就柔，强保边反而留噪 |

### 这个参数有多重要

鸣潮海报的实战数据：

| 配置 | 相似度 |
|---|---|
| 无保边平滑 | 89.9% |
| 中值滤波去噪（无回混） | 90.8% |
| LAB 量化 + 保边平滑 0.20 | **95.68%** |

**"保边平滑"一步贡献了 +4.9 个百分点**，是整个流程里性价比最高的环节。

## 二、`VEC_N` —— 调色板色数

### 拐点分析（碧蓝档案实测）

| 色数 | 相似度 | 文件体积 | 边际收益 |
|---|---|---|---|
| 40 | 96.79% | 4.8 MB | — |
| **64** | **97.10%** | **6.9 MB** | +0.31% / +44%体积 |
| 96 | 97.22% | 9.8 MB | +0.12% / +42%体积 |

**结论：64 色是拐点。** 超过 64 后体积线性增长而精度几乎不动。

### 按图片复杂度选

| 图片特征 | 建议色数 |
|---|---|
| 简单图形、少色扁平（logo、图标） | 24 ~ 32 |
| 省体积优先 | 40 ~ 48 |
| **通用推荐** | **56** |
| 复杂插画、颜色分散（主色占比 <15%） | 64 |
| 追求极限（不推荐） | 96 |

### 判断复杂度的方法

```python
from PIL import Image
import numpy as np
from collections import Counter
im = Image.open("图片.jpg").convert("RGB")
a = np.asarray(im)
q = (a // 16 * 16).reshape(-1, 3)
cnt = Counter(map(tuple, q))
top = cnt.most_common(1)[0][1] / len(q)
print(f"主色占比 {top*100:.1f}%")
# > 25%  → 简单，40 色够
# 15-25% → 中等，56 色
# < 15%  → 复杂，64 色
```

## 三、`VEC_W` —— 工作分辨率

**默认等于原图宽，不要降低。**

原因：细线条宽度可能只有 1-2 px，降采样后直接消失。
鸣潮海报测试：1280px 工作宽度时，人物发丝细节明显丢失。

例外：原图 > 4K（如 8K 截图）时，降到 2K 处理，并告知用户精度有损。

---

## 四、`VEC_EPS` —— RDP 简化容差

控制轮廓多边形简化的激进程度（Ramer-Douglas-Peucker 算法）。

| 值 | 效果 | 适用 |
|---|---|---|
| 0.2 | 极精细，点多，文件大 | 小尺寸图、细节密集 |
| **0.30** | **默认** | 通用 |
| 0.5 | 明显简化，曲线变折线 | 省体积 |
| 1.0+ | 过度简化，形状失真 | 不推荐 |

脚本内还有一个**自动分档**逻辑：小面积层用更小的 eps（保细节），
大面积层用更大的 eps（省体积）：

```python
eps = VEC_EPS * (1.0 if frac < 0.02 else (1.3 if frac < 0.10 else 1.8))
```

---

## 五、`VEC_MINAREA` —— 最小面积过滤（px²）

小于此面积的轮廓直接丢弃。

| 值 | 效果 |
|---|---|
| 3-5 | 保留最细节，但可能有杂点 |
| **5** | **默认** |
| 20-30 | 去杂点，适合照片类 |

配合"碎斑清理"使用（脚本内置：<24px 的连通块用邻域众数替换）。

---

## 六、`--layer-delay` —— 实时预览的层间延迟

仅 `live_vec_server.py` 使用，单位秒。

| 值 | 效果 |
|---|---|
| 0 | 全速，看不到过程 |
| **0.35** | **默认**，能看清逐层浮现 |
| 0.8 ~ 1.5 | 演示效果，56 层需要 45-85s |

**这是纯粹的视觉参数**，不影响输出质量。加了延迟只是把每层之间暂停一下，
让用户肉眼看到画面一层层长出来。总耗时 = 真实计算时间 + 层数 × 延迟。

## 八、四个实测样本的完整参数与结果

| 图片 | 尺寸 | VEC_N | VEC_EDGE | 相似度 | 体积 |
|---|---|---|---|---|---|
| 鸣潮 3.3 | 1920×1080 | 40 | 0.20 | 95.68% | 8.1 MB |
| 碧蓝档案 2nd | 1920×1080 | 64 | 0.14 | 97.10% | 6.9 MB |
| 崩坏学园2 | 1000×634 | 56 | 0.16 | 96.25% | 2.3 MB |
| 崩坏3rd | 1920×1080 | 56 | 0.20 | 96.52% | 5.5 MB |

**观察**：体积主要由像素总数决定，与色数相关但不是主导。
1000×634 的图只有 2.3 MB，而 1920×1080 的普遍 5-8 MB。

## 九、候选参数扫描（追求极限时用）

默认流程只跑一组参数。若用户明确要"最高还原度"，可跑 3-4 组候选、按 `compare.py`
的相似度择优。**代价是每组 1-2 分钟**，只在值得时做。

碧蓝档案 2nd（源图 `1691916375739.jpg`，1920×1080，1.2 MB）实测扫描结果：

| 候选 | VEC_N | VEC_EDGE | VEC_EPS | VEC_MINAREA | 相似度 | 体积 | 结论 |
|---|---|---|---|---|---|---|---|
| **①** | **96** | **0.14** | **0.26** | 5(默认) | **97.56%** | 7.9 MB | ✅ 最优，最终交付 |
| ② | 64 | 0.14 | 0.30 | 5(默认) | 97.35% | 6.2 MB | 体积优先时选它 |
| ③ | 72 | 0.10 | 0.30 | 10 | 97.29% | 5.9 MB | — |
| ④ | 64 | 0.14 | 0.30 | 14 | 97.14% | 5.3 MB | ❌ 去噪伤精度 |

三条可复用结论：

1. **同一张图，提高源文件质量也有收益**：本图另有一份 282 KB 的截图版本，
   64 色跑出 97.35%，而历史记录（低质源）只有 97.10%。
   **源图优先选体积大/压缩轻的那份**，同样参数能白赚 0.2-0.3 pp。
2. **`VEC_MINAREA` 调大是负收益**：从 5 提到 14，相似度掉 0.21 pp，只省 15% 体积。
   细碎色块在这类插画里是被"看见"的细节，不要激进去噪。
3. **96 色对这张图仍有 +0.21 pp 收益**（与历史"64 是拐点"的结论不冲突：
   拐点结论来自低质源，源图质量提高后拐点右移）。
   边际变小的原因不是色数无用，而是**源图本身更干净**。
