# 实时预览页面说明

`scripts/live_vec_server.py` 启动后自动打开的页面结构。**支持任意数量图片**。

---

## 一、整体布局

四栏：队列 | 原图 | 矢量重建 | 状态与日志

## 二、顶栏元素

| 元素 | 说明 |
|---|---|
| 标题 | 固定文案 |
| 阶段徽章 | 随 `phase` 变化（进行中蓝 / 完成绿 / 出错红） |
| 总进度徽章 | `已完成张数 / 总张数` |
| 进度条 | 宽度 = 当前图的 `layer / total_layers` |
| 层计数 | 当前图 `已完成 / 总层数` |

### 阶段（phase）取值

| phase | 中文显示 | 含义 |
|---|---|---|
| `init` | 初始化 | 服务刚启动 |
| `loading` | 读取图像 | 打开当前图、处理 alpha |
| `smooth` | 保边平滑 | 去噪 + 梯度回混 |
| `quantize` | 色彩量化 | LAB KMeans 聚类 |
| `trace` | 逐层描摹 | **用户最想看的阶段** |
| `done` | 完成 | 全部图处理完 |
| `error` | 出错 | 见日志区 |

> 注意：`phase` 反映的是**当前正在处理的图**；某张出错不会中断队列，会记在该图的
> `status` 上继续下一张。

## 三、左栏：图片队列

| 元素 | 说明 |
|---|---|
| 序号 | 1 起，灰色小字 |
| 文件名 | 超长省略，悬停显示全名 |
| 状态徽章 | `待处理`（蓝）/ `进行中`（紫）/ `完成`（绿）/ `失败`（红） |
| 相似度 | 仅完成的图显示，绿色 |

交互：
- **点击任意一项** → 中间两栏切换为该图（原图走 `/src/<i>`，矢量走 `/svg/<i>`）
- 当前处理中的项有蓝色左边框；正在查看的项有紫色左边框
- 点右栏「跟随当前」按钮 → 回到自动跟随当前处理图

## 四、右栏：状态字段

| 字段 | 数据来源 | 说明 |
|---|---|---|
| 阶段 | `STATE["phase"]` | 同顶栏 |

## 五、图片服务与缓存

| 路由 | 内容 | 缓存 |
|---|---|---|
| `/src/<i>` | 最长边 1400px 的 JPEG，质量 82 | `_SRC_CACHE` |
| `/thumb/<i>` | 最长边 220px 的 JPEG，质量 72 | `_THUMB_CACHE` |

均为**懒加载**（首次请求才生成），生成后驻留内存。这样启动时不必预读所有图，
浏览器打开更快。

## 六、性能设计（关键）

### 为什么 `/state` 要带版本号

一张 1920×1080 图的**中间态 SVG 可达数 MB**。原实现每 120ms 无条件回传整个 SVG，
在多层渲染时会造成海量无效流量与页面卡顿。

现在的做法：

```
客户端                        服务端
  ├── GET /state?v=57 ────────→
  │                             ├─ v(57) == STATE.version(57)? → 是
  │                             └─ svg 字段置空，只回状态
  ←── {svg:"", version:57} ─────┤
  │
  ├── GET /state?v=57 ────────→
  │                             ├─ 新完成一层，version=58
  ←── {svg:"<完整SVG>", v:58} ──┤   ← 只有版本变化时才传 SVG
```

客户端把 `version` 记在 `lastVer` 里，下次请求带上。

**实测**：版本未变时 `svg` 长度 = 0；版本变化时返回完整 SVG。

### 为什么用轮询而非 SSE / WebSocket

- **实现简单**：不需要管理长连接、心跳、重连
- **足够快**：120ms 轮询，人眼感知就是"实时"；全部完成后放慢到 900ms
- **无状态**：前端刷新页面不会断开
- **零依赖**：只要标准库 `http.server`

### 其他

- `STATE` 用 `threading.Lock` 保护（后台线程写，HTTP 线程读）
- 日志只回传最近 400 行，防止 JSON 过大
- 多图**串行**处理：避免多进程争抢 CPU 反而拖慢，也让用户能逐张看清

## 七、路由一览

| 路由 | 方法 | 返回 |
|---|---|---|
| `/` `/index.html` | GET | HTML 页面（单文件自包含，无外部依赖） |
| `/state?v=N` | GET | JSON 状态快照；版本未变时 `svg` 为空 |
| `/src/<i>` | GET | 第 i 张源图 JPEG |
| `/thumb/<i>` | GET | 第 i 张缩略图 JPEG |
| `/svg` | GET | 当前渲染中的 SVG |
| `/svg/<i>` | GET | 第 i 张已完成任务的 SVG（读磁盘） |
| 其他 | GET | 404 |

`/svg` 与 `/svg/<i>` 可用于直接下载或接入其他工具。

## 八、自定义

### 改配色

样式都内联在 `PAGE` 字符串里，搜索颜色值即可。当前是深色主题：

```
背景      #0f1117
面板      #161923 / #141721 / #131620
边框      #262a38 / #21242f
文字      #e6e8ef  次要 #7d86a3
强调      #5b7cfa → #8f6cff（进度条渐变）
选中      进行中 #5b7cfa 左边框 / 查看中 #8f6cff 左边框
```

> 预览图放在深底上更利于判断色彩与边缘，故默认深色。
> 若你更习惯浅色，把上述颜色反转即可。

### 改轮询间隔

```javascript
setTimeout(refresh, term ? 900 : 120);   // term = 全部结束
```

第一项是「全部完成后的慢速轮询」，第二项是「渲染中的快速轮询」。

### 加"下载 SVG"按钮

`/svg` 与 `/svg/<i>` 已就绪：

```html
<a href="/svg" download="result.svg">下载当前</a>
```

### 改队列宽度

```css
#queue{flex:0 0 200px; ...}    /* 200px → 你要的宽度 */
```

## 九、使用注意

1. **常驻进程**：跑完不会自动退出，看完要停（见 `references/pitfalls.md` 坑 7）
2. **端口冲突会自动换**：默认 8765，被占则 +1 重试最多 20 次，启动日志会打印实际地址
3. **`--layer-delay` 只影响观看体验**，不影响输出质量；多图时默认更小以免太久
4. **不要关掉终端**：关掉等于杀掉服务
5. 若浏览器没自动弹出，手动访问终端打印的 URL
6. 队列**只显示，不排序、不筛选**：按命令行给出的顺序处理
